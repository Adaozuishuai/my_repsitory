# 多 Agent 携程业务助手

本项目基于 **LangChain** 与 **LangGraph** 构建多 Agent 助手，适配携程的机票、酒店等业务流程，目标是让 AI 自主完成机票、酒店等全流程服务。

## 项目背景
大语言模型快速发展后，传统问答系统难以支撑复杂场景。本项目通过工作流式多 Agent 架构，实现业务工具的统一封装、状态可追溯、身份权限可管控以及主-子 Agent 的灵活调度。

## 技术栈
- 多 Agent 架构与工作流
- LangChain
- LangGraph

## 核心模块
### 1. 工具函数模块
- 针对携程业务工具调用分散、缺少统一分类的问题，将核心业务工具封装为 LangChain 工具。
- 按风险划分为「只读工具」与「敏感操作工具」，并按机票、酒店等五类业务分类后绑定至大模型，支持工具的动态触发与调用。

### 2. 状态管理模块
- 为解决工作流数据分散、追溯困难，设计 `State` 模块统一存储工作流历史消息、用户信息及工作流状态栈。
- 提供全流程数据可追溯、状态可管控的能力。

### 3. 身份权限控制模块
- 通过主 Agent 调用 `fetch_user_info` 获取旅客 ID，并将信息存入 `State`，确保上下文统一。
- 在敏感工具调用前触发 `interrupt_before` 进行中断校验，结合 `MemorySaver` 与 `thread_id`、旅客 ID 的双重校验，保障权限可控。

### 4. 多 Agent 调度模块
- 主 Agent 负责调度机票、酒店等四类子 Agent，并为各子工作流配置五类核心节点。
- 通过 `add_conditional_edges` 实现主-子流程的动态路由，借助 `update_dialog_stack` 规范回调逻辑，提升多业务协同效率。
